# 实现过程与设计说明

## 1. 原项目问题与改造目标

原脚本先生成日语再翻译中文，与需求顺序相反；模型在模块导入时加载，难以测试；音频播放和降级合成启动后台线程后立即弹窗，不能保证音频已经就绪；缺少关键点置信度检查，丢失用户后计时可能延续；退出使用强制结束进程，清理函数还引用了未导入的 glob。

改造将检测、计时、外部服务、呈现分离。保留原启动方式及原始脚本副本，不复制原来的大批无关依赖。保留原仓库 LICENSE，第三方模型和库按各自许可证使用。

## 2. 视觉检测

加载 `yolov8n-pose.pt`，每次读取一帧并执行推理。从 COCO 关键点取鼻子0、左肩5、右肩6，只接受单人且三个点置信度都足够的结果。默认计算有符号垂直距离，与原算法保持一致，并非鼻子到每个肩膀的欧氏距离。

像素模式受画面分辨率、人与摄像头距离影响；比例模式用双肩欧氏距离归一化，肩宽接近零时拒绝计算。两种模式都需要手动标定。多人画面直接暂停，避免把不同人的连续时间合并；尚未实现身份追踪，单人无缝替换等场景仍属于边界情况。

## 3. 连续计时

使用 `time.monotonic()` 避免系统时间调整影响计时。首次异常记录开始时刻，后续异常帧累积实际经过时间。达到持续时间后立即进入同步生成流程，不再调度新检测帧，因此不会产生重复生成任务。

正常、无效点、无人、多人均清零；采样间隔过长也清零，避免暂停后直接“补算”异常时间。确认后从确认时间起冷却，冷却结束后重新开始完整持续时间。生成失败使用独立重试延迟，同样要求重新观察连续异常。

## 4. 中文生成与持久化

Qwen 接收“用户坐姿异常持续多少秒”的描述，以及只吐槽坐姿、提醒坐直的中文提示词。`Pipeline.prepare()` 获取中文后立即将其写入唯一 UUID 命名的 JSON，状态为 `chinese_saved`，再发起翻译请求。

本地后端通过聊天模板构建输入，只解码新生成 token。API后端使用 `/v1/chat/completions`，关闭stream。两者共用 `complete()` 接口；本地后端首次启动加载一次模型，后续复用。文本会检查是否为空或过长；语言与一句话风格主要由提示词约束，仍需用真实模型检查翻译质量。

## 5. 翻译与音色生成

第二次Qwen调用输入的就是已经保存的中文，而不是重新生成的另一句话。随后向 `http://127.0.0.1:9880/tts` 发送日文：目标语言固定 `ja`，参考音频语言独立配置，`streaming_mode=false`，`media_type=wav`。

接口等待完整响应，通过标准库wave解析PCM WAV并核对声明帧数和实际数据长度，拒绝JSON错误、空数据和截断音频。音频保存在内存中，避免临时文件重名和Windows播放文件锁问题。支持官方非流式PCM WAV；其他编码需先调整服务输出。

成功后JSON状态为 `audio_ready`，该状态只表示生成就绪，不表示用户已听完或确认。翻译或TTS错误保存 `failed` 和错误信息，再向上抛出。中文生成前发生故障只记日志，因为此时尚无中文可保存。

## 6. 弹窗与声音的同步边界

`present_alert()` 接受包含中文、日文、完整音频的不可变结果。先初始化播放器、解码音频、取得播放通道；任何一步失败都不会展示警告。然后构建隐藏的Tk窗口，填入已经保存的中文。在同一个调用中执行显示和声音启动，期间不做网络请求或模型推理。

弹窗使用 `grab_set()` 和 `wait_window()`，语音由音频设备播放，Tk继续处理确认按钮。应用没有新建生成/播放线程，也没有async调用。不能用“等音频全部播完再运行弹窗”的阻塞方式，否则无法做到同时出现。

右上角关闭键不执行关闭，播放结束也不关闭；点确定停止声音并销毁窗口。操作系统和设备会引入刷新/播放延迟，软件保证的是同一准备完成屏障，而不是物理时间完全一致。

## 7. 资源与失败恢复

正常退出释放摄像头，关闭Tk并退出音频混音器，不使用 `os._exit()`。日志按2MB轮转、保留3份。历史JSON持续保存，需按用户需要定期归档或删除；原始摄像头帧不落盘。

默认所有服务使用回环地址。切换API地址时只有提醒文本发送给Qwen和TTS，摄像头帧仍在本进程检测。模型加载或摄像头打开失败时退出并给出错误。检测运行中断开摄像头则停止检测，需退出重启。

严格串行意味着模型加载、推理、HTTP等待时界面暂停。若未来要求界面始终响应，应单独讨论后台工作线程，但仍必须保持“完整音频准备好才发布警告”的屏障；本版按当前需求未采用这种设计。

## 8. 人工端到端验收

1. 使用 `--check-config` 排除配置结构错误；它不探测摄像头或网络。
2. GPT-SoVITS加载已有权重和参考音频后，运行 `--test-alert`。检查历史中文存在、日语含义对应、音色正确、窗口不先等待语音生成。
3. 语音结束后等待10秒，窗口仍应存在；点右上角关闭无效，点确定应关闭。播放中点确定应同时停止声音。
4. 启动检测，正常坐姿不计时；短于duration的异常应在恢复后清零；连续异常达到duration只出现一次提醒。
5. 鼻子或肩膀遮挡、离开画面、第二人进入时计时清零，不触发。
6. 点确定后冷却期内不再次提醒，之后仍异常则需重新达到duration。
7. 停止TTS服务后触发提醒：不得出现无声中文警告，应显示错误并保留中文历史；恢复服务后，等待重试延迟并重新保持异常可再次尝试。
8. 调整窗口、相机位置和光照，重新标定阈值；记录误报率和漏报情况。更换分辨率后重新标定像素阈值。

## 9. 测试范围与扩展方向

自动测试使用假Qwen和假TTS验证确定性业务逻辑，不下载权重。真实GPU兼容性、翻译自然度、音色效果、摄像头帧率、实际弹窗与声音延迟需要目标机器验收。后续可扩展自动标定、指定用户跟踪和肩颈角度组合判断，但不把这些未实现功能列为已完成。
